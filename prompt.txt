You are working on an existing Python project called NetScope, a program that
checks the network state of the device it runs on. Read the existing codebase
first and summarize its structure before changing anything. Keep what works,
refactor only where needed, and do not rewrite from scratch.

======================================================================
## 0. GOAL
======================================================================
Evolve NetScope into a universal, lightweight Windows network troubleshooting
tool. It diagnoses problems, explains them in plain language, offers preset
fixes the user can apply, and, when a fix does not work, explains the probable
causes (on this device and beyond it) and what to check next. Fixes are
limited to the end device (local network configuration only). "End device"
means the PC NetScope runs on.

NetScope has two first-class front ends on one shared engine:
- A CLI that network engineers can use as a real tool: scriptable, pipeable,
  fast, keyboard-driven.
- A GUI for normal users: buttons, plain language, guided fixes.
Neither front end contains business logic. Both call the same core engine, so
behavior, results, and logs are identical.

======================================================================
## 1. PACKAGING AND LAUNCH
======================================================================
- Ship as a single lightweight netscope.exe (PyInstaller --onefile, or Nuitka
  if it gives a smaller exe). Use the standard library wherever possible
  (argparse, tkinter, subprocess, socket, ctypes, logging, json). Avoid heavy
  dependencies. Report the final exe size.
- The user launches it by typing `netscope` in cmd, PowerShell, Win + R, or
  Windows Start search, the way VS Code does with `code`. Provide
  `netscope install`, which copies the exe to
  %LOCALAPPDATA%\Programs\NetScope, adds that folder to the user PATH,
  registers the App Paths key
  (HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\netscope.exe),
  and creates a Start Menu shortcut. Also provide `netscope uninstall`.
  Broadcast WM_SETTINGCHANGE after the PATH change.

### Dual-mode behavior (the exe works as a CLI tool AND a GUI app)
- Build as a console-subsystem exe so stdout/stderr/stdin work properly in
  terminals and when piped or redirected.
- Mode selection:
  - Any subcommand or flag given -> CLI mode, output stays in the terminal.
  - No arguments and launched from an existing terminal -> open the
    interactive CLI shell (see section 2), NOT the GUI. Offer `netscope gui`
    to open the GUI from a terminal.
  - No arguments and launched from Win + R, Start search, or a double-click
    (detect via GetConsoleProcessList: the process owns its own console) ->
    hide/detach that console with ctypes and open the GUI.
- Avoid a stray console window or flash when the GUI launches. If a single exe
  cannot fully avoid the flash from Win + R, propose and implement the best
  alternative (for example a tiny windowless launcher netscope-gui.exe used by
  the Start Menu shortcut) and explain the tradeoff.
- Detach the GUI from the terminal when launched via `netscope gui` so the
  prompt returns immediately.

======================================================================
## 2. CLI (first-class, for network engineers)
======================================================================
Use argparse with subcommands, proper --help for each, and consistent flags.

Subcommands:
- `netscope` (no args, in a terminal): interactive shell with a prompt
  (`netscope>`), command history, tab completion where possible, and a
  numbered menu fallback for beginners. Commands inside the shell mirror the
  subcommands.
- `netscope diagnose [--layer adapter|ip|gateway|lan|dns|internet|stack]`
  runs the full pipeline or a single layer.
- `netscope fix [finding-id] [--yes] [--dry-run]` guided fix flow in the
  terminal: shows the finding, cause, exact commands, admin/risk/reboot info,
  asks `Proceed? [y/N]`, runs, then re-checks and reports.
- `netscope info [--adapter NAME]` network configuration: adapters, IPs,
  gateway, DNS, DHCP, MAC, MTU, routes, ARP table, proxy, VPN, Wi-Fi details.
- Built-in utilities so engineers don't need to leave the tool, all logged:
  `ping`, `trace`, `dns <name> [--server IP]`, `arp`, `routes`,
  `ports <host> <ports>` (TCP connect test), `mtu <host>` (path MTU probe).
- `netscope logs [--tail N] [--open] [--export FILE]`
- `netscope report [--output FILE] [--format txt|json]`
- `netscope gui`, `netscope install`, `netscope uninstall`, `netscope --version`

CLI behavior requirements:
- Global flags: `--json` (machine-readable output), `--no-color`, `--quiet`,
  `--verbose`, `--yes` (non-interactive confirm for fixes), `--dry-run`.
- Color and symbols (pass/warn/fail) with automatic fallback when output is
  piped, NO_COLOR is set, or the terminal does not support ANSI. Enable
  Windows virtual terminal processing via ctypes.
- Meaningful exit codes: 0 all pass, 1 warnings, 2 failures remain (including
  unresolved after fixes), 3 fix failed, 4 needs admin, 64 usage error.
  Document them in --help and README.
- Stream progress live (each check prints as it completes with a spinner or
  simple status line) and handle Ctrl+C cleanly (kill child processes, log the
  interruption, restore the terminal).
- Output must be pipe-friendly (stdout for results, stderr for progress and
  errors) and must never prompt when stdin is not a TTY unless --yes is given.
- Admin handling: detect elevation up front. If a fix needs admin and the
  session is not elevated, say so and offer to relaunch elevated (UAC) or
  print the exact command to run from an admin terminal.

======================================================================
## 3. TROUBLESHOOTING ENGINE
======================================================================
Build a modular diagnostic pipeline that runs checks in order, from the local
device outward, and highlights the first failing layer:
1. Adapter status (disabled, disconnected, no media, driver errors, power
   saving, link speed)
2. Services the network depends on (WlanSvc, Dhcp, Dnscache, NlaSvc/netprofm,
   BFE, LanmanServer/Workstation and discovery services)
3. IP configuration (APIPA 169.254.x.x, no gateway, wrong subnet, duplicate
   address, DHCP failure, bad routes, overlapping routes)
4. Gateway reachability (ping, ARP entry for the gateway)
5. Local peers (can't reach other LAN devices -> ARP, profile, firewall, SMB,
   NetBIOS)
6. DNS (resolve fails while pinging raw IPs works; hosts file overrides)
7. Internet reachability (ping 1.1.1.1 / 8.8.8.8, HTTP probe, captive portal,
   proxy, system clock)
8. Cross-cutting: VPN, Wi-Fi quality, MTU, performance, firewall/security
   software, Winsock/TCP-IP stack corruption

Each check returns a structured result: id, layer, status (pass/warn/fail),
what was found, the likely cause, evidence (raw data), and suggested fix IDs.
The engine returns plain data objects. Front ends only render them.

======================================================================
## 3A. FIX CATALOG ARCHITECTURE (data-driven)
======================================================================
Store the catalog as data (fixes.json or similar), one object per entry,
loaded by the engine. Each entry has:
- id, name, symptom, detection signal (how the engine decides it applies)
- fix commands (PowerShell primary, native fallback)
- plain-language explanation of what the fix does and why
- admin required (Y/N), risk (L/M/H), reboot needed (Y/N)
- pre-fix snapshot (what state to record before changing anything)
- rollback (how to undo)
- verification check (what to re-run afterward)
- fix ladder (safest first, then escalate)
- if_unresolved block (see section 3D)
Entries tagged DETECT-ONLY never run commands; they explain the cause and what
the user must check outside the device. Entries tagged [VERIFY] must be
tested on a real machine before release.

======================================================================
## 3B. COMMAND EXECUTION LAYER (PowerShell-first)
======================================================================
- Use Windows PowerShell 5.1 (powershell.exe, present on every Windows 10/11).
  Do not require PowerShell 7 or bash/WSL.
- Prefer cmdlets that return objects (Get-NetAdapter, Get-NetIPConfiguration,
  Get-NetRoute, Get-NetNeighbor, Get-DnsClient*, Test-NetConnection,
  Get-NetFirewallRule, Get-SmbClientConfiguration, Get-Service). Output via
  ConvertTo-Json -Depth 4, parsed in Python. This avoids localized-output
  parsing.
- Use native exes only where no good cmdlet exists: netsh (winsock, int ip
  reset, wlan, winhttp, interface tcp), ipconfig, arp, route, nbtstat, w32tm,
  cmdkey, ping, pathping, tracert.
- Launch with: powershell.exe -NoProfile -NonInteractive
  -ExecutionPolicy Bypass. Scripts come ONLY from the catalog. User-supplied
  values (adapter name, host, port, profile name) are validated with a strict
  regex/allowlist in Python AND passed as parameters (param() block), never
  string-concatenated into script text.
- Batch related checks into one PowerShell process (startup costs about
  0.3-0.5 s). Do fast things in pure Python (socket connect tests, DNS via
  socket).
- Detect Constrained Language Mode / AppLocker restrictions at startup
  ($ExecutionContext.SessionState.LanguageMode). If blocked, fall back to the
  native exe equivalent and tell the user.
- All system calls go through ONE thin command-runner interface that can be
  mocked in tests.

## 3C. FIX CATALOG SEED DATA
======================================================================
Implement these entries as the initial catalog. For every entry, also record
the snapshot and rollback fields where a setting is changed.

### A. ADAPTER AND DRIVER
ADP-01 Adapter disabled
  detect: Get-NetAdapter Status=Disabled
  fix: Enable-NetAdapter -Name <n>   | admin Y, risk L, reboot N
ADP-02 Link up but no traffic / adapter hung
  detect: Status Up, gateway unreachable, ARP incomplete
  fix: Restart-NetAdapter -Name <n>  | admin Y, risk L, reboot N
ADP-03 Random disconnects / drops after sleep (power saving cuts the adapter)
  detect: Get-NetAdapterPowerManagement AllowComputerToTurnOffDevice=Enabled
  fix: Set-NetAdapterPowerManagement -Name <n>
       -AllowComputerToTurnOffDevice Disabled
  admin Y, risk L, reboot N, rollback: set back to Enabled
ADP-04 Driver error (Code 10/43) or generic driver glitch
  detect: Get-PnpDevice -Class Net with Status Error/Degraded
  fix: Disable-PnpDevice then Enable-PnpDevice (admin Y, risk M).
       Driver update/reinstall = DETECT-ONLY advice (tell the user which
       adapter and to use the vendor driver).
ADP-05 Ethernet negotiated at wrong speed/duplex (10 Mbps / half duplex)
  detect: Get-NetAdapter LinkSpeed far below expected
  fix: Set-NetAdapterAdvancedProperty -Name <n> -DisplayName "Speed & Duplex"
       -DisplayValue "Auto Negotiation"  (property names vary by driver; skip
       gracefully if absent). If still low: DETECT-ONLY, suspect cable/port.
  admin Y, risk M, reboot N
ADP-06 Wrong interface chosen (virtual adapter wins routing)
  detect: Get-NetIPInterface lowest InterfaceMetric belongs to Hyper-V/WSL/
          VPN/virtual adapter while the physical one is idle
  fix: Set-NetIPInterface -InterfaceAlias <n> -InterfaceMetric <value>
  admin Y, risk M, rollback: restore recorded metric (or Automatic)

### B. WINDOWS SERVICES THAT NETWORKING DEPENDS ON
SVC-01 WLAN AutoConfig (WlanSvc) stopped/disabled -> Wi-Fi missing or flaky
SVC-02 DHCP Client (Dhcp) stopped -> no/APIPA address
SVC-03 DNS Client (Dnscache) stopped -> name resolution fails
SVC-04 Network Location Awareness (NlaSvc) / Network List Service (netprofm)
       stuck -> wrong "No Internet" status, wrong profile
SVC-05 Base Filtering Engine (BFE) stopped -> firewall/VPN failures
SVC-06 File-sharing stack: LanmanServer, LanmanWorkstation, FDResPub,
       SSDPSRV, upnphost stopped -> shares/devices not visible
  detect (all): Get-Service <name> Status!=Running or StartType=Disabled
  fix (all): Set-Service <name> -StartupType Automatic; Restart-Service/
       Start-Service <name>
  admin Y, risk L, reboot N, rollback: restore recorded StartType

### C. IP / DHCP / ROUTING
IP-01 APIPA (169.254.x.x) or no lease
  detect: Get-NetIPAddress PrefixOrigin=WellKnown/169.254.*
  ladder: 1) ipconfig /release + ipconfig /renew
          2) Restart-NetAdapter
          3) Restart-Service Dhcp
          4) if still APIPA -> DETECT-ONLY: DHCP server/router not answering
             (check router, cable, AP, VLAN)
  admin Y, risk L, reboot N
IP-02 Stale lease / wrong subnet after moving between networks
  detect: IP not in the same subnet as the reachable gateway; lease expired
  fix: ipconfig /release; ipconfig /renew   | admin Y, risk L
IP-03 Duplicate IP address on the LAN
  detect: Get-NetIPAddress AddressState=Duplicate (or Event ID 4199)
  fix: switch interface to DHCP (Set-NetIPInterface -Dhcp Enabled; remove the
       static address with Remove-NetIPAddress; Set-DnsClientServerAddress
       -ResetServerAddresses); then renew. Tell the user which MAC conflicts
       if ARP shows it.
  admin Y, risk M, rollback: re-apply recorded static config
IP-04 Static IP/mask/gateway wrong for the network
  detect: static config, gateway not reachable on-link, mask mismatch
  fix: offer switch to DHCP (same as IP-03). Never guess a static address.
  admin Y, risk M
IP-05 Missing or wrong default route
  detect: Get-NetRoute 0.0.0.0/0 absent, or points to a dead/unreachable hop
  fix: Remove-NetRoute for the bad entry, then renew DHCP to recreate it.
  admin Y, risk M
IP-06 Leftover/overlapping routes (often after VPN or virtual switches)
  detect: duplicate destination prefixes in Get-NetRoute; persistent routes
  fix: Remove-NetRoute for the specific stale route; adjust InterfaceMetric.
       `route -f` is a last resort: clears ALL routes, breaks VPN. risk H,
       requires a second explicit confirmation.
  admin Y, reboot N (route -f: Y)
IP-07 Docker/WSL/Hyper-V virtual network overlaps a real LAN or VPN range
  detect: local virtual adapter prefix overlaps the prefix of the physical
          LAN/VPN (commonly 172.16-31.x.x)
  fix: DETECT-ONLY with explanation; optionally lower the virtual adapter's
       metric (ADP-06).
IP-08 IPv6 broken (sites hang while IPv4 works; AAAA answered first) [VERIFY]
  detect: Test-NetConnection over IPv6 fails while IPv4 succeeds; IPv6
          address present but no working v6 gateway
  fix (workaround): prefer IPv4 via registry
       HKLM\SYSTEM\CurrentControlSet\Services\Tcpip6\Parameters
       DisabledComponents=0x20 (reboot), or Disable-NetAdapterBinding
       -ComponentID ms_tcpip6 on that adapter (less preferred).
  admin Y, risk M, reboot Y (registry), rollback: restore value/binding

### D. LOCAL NETWORK / ARP / FILE SHARING
LAN-01 Stale or poisoned ARP cache (can't reach local devices)
  detect: ARP entry for gateway/peer maps to a wrong MAC or is Unreachable/
          Stale while the device is up
  ladder: 1) Remove-NetNeighbor -Confirm:$false  (or arp -d *)
          2) netsh interface ip delete arpcache
          3) Restart-NetAdapter
  admin Y, risk L, reboot N
LAN-02 Gateway ARP stays "incomplete"/unreachable
  detect: no ARP reply from the gateway after LAN-01
  fix: DETECT-ONLY: cable, switch port, Wi-Fi association, wrong VLAN,
       router down.
LAN-03 Can reach gateway and internet but not other LAN devices
  detect: gateway ping OK, peer ping fails, peer ARP incomplete
  fix: DETECT-ONLY: Wi-Fi client/AP isolation or guest network on the
       router; peer's firewall blocking ICMP (test by TCP port too).
LAN-04 Network profile is Public (discovery and sharing blocked)
  detect: Get-NetConnectionProfile NetworkCategory=Public on a trusted LAN
  fix: Set-NetConnectionProfile -InterfaceAlias <n> -NetworkCategory Private
  admin Y, risk M (confirm the network is trusted), rollback: set Public
LAN-05 Discovery/sharing firewall rules disabled
  detect: Get-NetFirewallRule -DisplayGroup "Network Discovery" and
          "File and Printer Sharing" Enabled=False
  fix: Enable-NetFirewallRule -DisplayGroup "Network Discovery";
       Enable-NetFirewallRule -DisplayGroup "File and Printer Sharing"
       (native: netsh advfirewall firewall set rule group="..." new
       enable=Yes)
  admin Y, risk M, rollback: disable the same groups
LAN-06 NetBIOS name resolution failing (\\NAME not found, \\IP works)
  detect: \\IP reachable on 445 but \\NAME fails; NetBIOS over TCP/IP off
  fix: nbtstat -R; nbtstat -RR; enable NetBIOS over TCP/IP on the adapter
       (Win32_NetworkAdapterConfiguration.SetTcpipNetbios)
  admin Y, risk L
LAN-07 Port 445 (SMB) unreachable
  detect: Test-NetConnection <host> -Port 445 fails while ping works
  fix: DETECT-ONLY (remote firewall, ISP blocks 445, or local rule). Check
       local outbound block rules on 445 first.
LAN-08 SMB2/3 client disabled
  detect: (Get-SmbClientConfiguration).EnableSMB2Protocol=False
  fix: Set-SmbClientConfiguration -EnableSMB2Protocol $true
  admin Y, risk L, reboot N
LAN-09 Legacy device needs SMB1 or insecure guest logon
  detect: SMB negotiation fails against NAS/old device; error "organization's
          security policies block unauthenticated guest access"
  fix: DEFAULT = DETECT-ONLY with a security warning. Optional fix behind a
       second explicit confirmation: set AllowInsecureGuestAuth=1
       (HKLM\SOFTWARE\Policies\Microsoft\Windows\LanmanWorkstation).
       Enabling the SMB1 client is NOT offered.
  admin Y, risk H, rollback: restore recorded value
LAN-10 SMB signing mismatch [VERIFY]
  detect: access denied/"network path not found" only against specific
          devices, signing required on one side
  fix: DETECT-ONLY by default (disabling signing weakens security).
LAN-11 Cached bad credentials (repeated password prompts, access denied)
  detect: cmdkey /list shows stale entries for the target
  fix: cmdkey /delete:<target>; net use <target> /delete
  admin N, risk L, rollback: none (user re-enters password)

DNS-01 Stale or poisoned DNS cache
  detect: Resolve-DnsName result differs from a direct query to a public DNS
  fix: Clear-DnsClientCache (ipconfig /flushdns); ipconfig /registerdns
  admin Y, risk L
DNS-02 DNS server unreachable or failing while IP connectivity works
  detect: ping 1.1.1.1 OK, resolve fails, configured DNS fails
  ladder: 1) Set-DnsClientServerAddress -ResetServerAddresses (back to DHCP)
          2) set 1.1.1.1/8.8.8.8 on the adapter (record previous servers)
          3) if public DNS also fails: DETECT-ONLY (port 53 filtered/
             captive portal/firewall)
  admin Y, risk L-M, rollback: restore recorded servers
DNS-03 Hosts file overrides (leftover blocklists, malware, old dev entries)
  detect: non-comment entries in %SystemRoot%\System32\drivers\etc\hosts,
          especially for popular domains or 0.0.0.0 blocks
  fix: back up the file to the NetScope data folder, show a diff, remove only
       the entries the user selects (or restore the default)
  admin Y, risk M, rollback: restore backup
DNS-04 VPN split-DNS / NRPT leaves internal names unresolvable [VERIFY]
  detect: internal names fail on VPN; Get-DnsClientNrptPolicy lacks a rule or

  fix: Clear-DnsClientCache; reconnect VPN; DETECT-ONLY otherwise
DNS-05 Encrypted DNS (DoH) misconfigured [VERIFY]
  detect: Get-DnsClientDohServerAddress entries present, resolves fail only

  fix: DETECT-ONLY, tell the user which setting to review

NET-01 Captive portal (hotel/cafe/campus Wi-Fi) blocking access

  fix: open the system browser to a plain HTTP page (e.g. http://neverssl.com)

NET-02 Windows says "No Internet" but browsing works (false negative)

  ladder: 1) Restart-Service NlaSvc (and netprofm)
          2) Restart-NetAdapter

  admin Y, risk L
NET-03 Stale/wrong WinHTTP system proxy (Windows Update, Store and services

  detect: netsh winhttp show proxy returns a proxy that is unreachable
  fix: netsh winhttp reset proxy   | admin Y, risk L,

NET-04 Dead per-user (WinINET) proxy
  detect: HKCU\...\Internet Settings ProxyEnable=1 and ProxyServer

NET-05 Dead PAC / auto-config URL

NET-07 Local firewall blocking traffic

NET-08 Third-party security software interfering [VERIFY]

NET-10 Slow throughput / slow file copy or RDP to older servers

### H. WI-FI
WIFI-01 Corrupted or outdated saved profile (connects but no internet, auth

  detect: repeated auth failure events, or association OK + no IP,

  fix: netsh wlan export profile name="<n>" folder=<dir>  (do NOT use

  admin Y, risk M, rollback: netsh wlan add profile filename=<file>
WIFI-02 Weak signal, low link rate, congested channel/band
  detect: netsh wlan show interfaces (Signal, Radio type, Channel, Rate);
          netsh wlan show networks mode=bssid for neighboring channels

  action: netsh wlan show wlanreport (admin); open the generated HTML. Not a

  detect: adapter present, radio off (software switch)

### I. STACK RESET LADDER (last resorts, always show the warning)
STK-01 Winsock catalog corrupted (error 10106/10093, third-party LSP issues)
  fix: netsh winsock reset   | admin Y, risk M, reboot Y
STK-02 TCP/IP stack corrupted
  fix: netsh int ip reset; netsh int ipv6 reset  | admin Y, risk M, reboot Y
STK-03 Standard sequence when higher-level fixes failed:
  ipconfig /release -> Clear-DnsClientCache -> netsh winsock reset ->
  netsh int ip reset -> reboot -> re-run diagnose
STK-04 Windows "Network reset" (removes and reinstalls all adapters, resets
  VPN/virtual adapters and saved settings): NOT run by NetScope; DETECT-ONLY
  final recommendation with a warning that Wi-Fi passwords and VPN adapters
  will be lost.

### J. FINDINGS THAT CANNOT BE FIXED FROM THIS DEVICE (always say so honestly)
- Gateway ARP never resolves / link down: cable, port, AP, router power.
- DHCP server not answering: router/DHCP service/VLAN.
- Gateway reachable but nothing beyond it: router WAN, modem, ISP outage.
- DNS fails on every resolver including public ones on port 53: upstream
  filtering or ISP block.
- Only one site fails: remote server problem; show traceroute/pathping.
- Peer unreachable only by Wi-Fi: AP isolation or guest SSID.
Each shows what to check next and never claims a fix.

======================================================================
## 3D. "IF NOT RESOLVED" ENGINE (probable causes after a failed fix)
======================================================================
Every catalog entry has an `if_unresolved` block:
  this_device: probable causes on the machine itself that NetScope cannot
               fix with settings (hardware, driver, OS, security software)
  beyond_device: probable causes outside the machine
  next_checks: 1-3 concrete things the user can try or inspect, in order,
               cheapest first
  evidence_to_collect: what NetScope captures for the report

Rules:
- Show it ONLY after the fix ladder is exhausted and the re-check still
  fails. Do not show it while untried fixes remain.
- When it is reached, ask or test: "Does another device on the same network
  work?" (CLI: a y/n/unknown prompt, skipped with --yes or non-TTY; GUI: a
  small question). Record the answer and use it, together with the collected
  evidence, to rank this_device vs beyond_device causes.
- Rank causes by likelihood given the evidence (for example, if the link is
  up and the gateway ARP is incomplete, rank "cable/port/AP" above "NIC
  failure").
- Phrase as "probable" or "possible", never as a diagnosis. Never claim a
  hardware fault without evidence (link state, error counters, event IDs).
- Log the unresolved result, the causes shown, the evidence, and the answer
  to the isolation question.
- The exported report includes this section for every unresolved finding.
- CLI: print it under the finding with exit code 2. GUI: an expandable
  "Still not working? Likely causes" panel.

Seed data for if_unresolved:

ADAPTER / DRIVER (ADP-01..06)
  this_device: failing or loose NIC (PCIe/USB/M.2 Wi-Fi card), faulty or
    incompatible driver, BIOS/UEFI disabled the device, USB adapter or dock
    issue, Wi-Fi hardware switch/Fn key off, corrupted OS network components,
    overheating or power-starved USB adapter
  beyond_device: bad cable, dead switch port, failing wall jack, PoE or
    switch port security disabling the port, router/AP down
  next_checks: try a different cable/port, test another USB port/adapter,
    check Device Manager error code and Event Viewer (NDIS and vendor driver
    sources), update or roll back the driver from the vendor
  evidence: Get-NetAdapter Status/LinkSpeed, Get-PnpDevice status and
    problem code, Get-NetAdapterStatistics errors/discards

SERVICES (SVC-01..06)
  this_device: service dependency missing or corrupted, service disabled by
    group policy or security/optimizer tool, corrupted system files, failed
    Windows update leaving components broken
  beyond_device: managed device (domain/MDM policy re-disables the service)
  next_checks: sfc /scannow, DISM /Online /Cleanup-Image /RestoreHealth,
    check gpresult / MDM policy, check for "PC optimizer" tools
  evidence: service state and start type, service-start failure event IDs

IP / DHCP (IP-01..04)
  this_device: NIC/driver not passing traffic, static address left from
    another network, virtual adapter (VPN, Hyper-V, Docker) interfering,
    wrong adapter being configured, security software blocking DHCP
  beyond_device: DHCP server down or scope exhausted, router needs reboot,
    MAC filtering/NAC rejecting the device, wrong VLAN or SSID, rogue DHCP
    server handing out bad settings, duplicate IP on the LAN
  next_checks: connect directly to the router or another port/SSID, check
    the router's DHCP lease table for free addresses and this MAC, reboot
    the router, test with a different device on the same port
  evidence: assigned address, lease info, DHCP server address if any,
    APIPA flag, adapter MAC

ROUTING (IP-05..07)
  this_device: VPN or virtual switch left routes behind, security tool
    rewriting routes, multiple active adapters with competing metrics,
    corrupted persistent routes
  beyond_device: gateway down or advertising the wrong route, upstream
    routing change, overlapping subnets between sites
  next_checks: disconnect VPN/virtual adapters, disable unused adapters,
    compare route print against a known-good machine, tracert to see where
    the path dies
  evidence: Get-NetRoute dump, interface metrics, first failing hop

IPv6 (IP-08)
  this_device: broken IPv6 stack or tunnel adapter (Teredo/6to4), security
    software filtering v6
  beyond_device: ISP/router advertising IPv6 but not routing it, router
    RA/firewall bugs
  next_checks: test with IPv6 disabled on the adapter, check router IPv6
    settings, update router firmware
  evidence: v4 vs v6 test results, v6 gateway, RA presence

LOCAL NETWORK / ARP (LAN-01..03)
  this_device: NIC offload or driver bug, VPN/virtual adapter capturing LAN
    traffic, host firewall blocking ICMP, wrong adapter selected
  beyond_device: Wi-Fi AP/client isolation or guest network, switch port
    security or MAC filtering, the peer is offline/asleep or has its own
    firewall, VLAN separation, failing switch/cable, IP conflict with another
    device
  next_checks: test with a wired connection, test peer reachability from a
    third device, check router client list and isolation setting, test by TCP
    port instead of ping
  evidence: ARP table state per peer (Reachable/Stale/Incomplete), gateway
    vs peer results, subnet match

FILE SHARING / SMB (LAN-04..11)
  this_device: stale or conflicting saved credentials, Credential Manager
    corruption, local policy (insecure guest logon, signing, NTLM
    restrictions), third-party firewall, SMB client disabled by policy,
    clock skew breaking Kerberos
  beyond_device: host's share/NTFS permissions wrong, host firewall or
    network profile Public, host SMB version/security mismatch (NAS with
    SMB1 only), host sleeping, ISP blocking port 445, server out of
    sessions, wrong name or IP
  next_checks: connect by IP vs name, test \\host\IPC$, try from another PC,
    check host's Sharing tab and event logs, verify the same user exists on
    the host
  evidence: port 445 result, SMB dialect negotiated, error code (0x80070035,
    0x80004005), net use output

DNS (DNS-01..05)
  this_device: security/VPN software hijacking DNS, corrupted DNS client
    service, hosts file or proxy overriding resolution, wrong adapter DNS
    order, DoH policy conflict, stale NRPT rules
  beyond_device: ISP/router resolver down or slow, router DNS proxy bug,
    port 53 blocked or intercepted, captive portal, content filter blocking
    domains, upstream outage for that domain only
  next_checks: query a public resolver directly (nslookup name 1.1.1.1), try
    another device on the same network, reboot the router, check the router's
    DNS setting
  evidence: per-resolver results and latency, NXDOMAIN vs timeout vs
    SERVFAIL, hosts file hits

INTERNET / PROXY / CAPTIVE PORTAL (NET-01..06)
  this_device: browser or app-level proxy or extension, security software
    HTTPS inspection, wrong system clock, expired or intercepted
    certificates, malware changing settings, per-app firewall rule
  beyond_device: router WAN down, modem not synced, ISP outage or billing
    block, captive portal not completed, upstream proxy/auth required,
    corporate firewall policy, remote site down
  next_checks: check modem/router WAN light and status page, test on another
    device or phone hotspot, call ISP, open a plain HTTP page to trigger a
    portal, test another site/app
  evidence: gateway ping, public-IP ping, DNS result, HTTP/HTTPS probe
    results, proxy settings found

FIREWALL / SECURITY SOFTWARE (NET-07, NET-08)
  this_device: third-party antivirus/firewall web protection, corrupted
    firewall policy, VPN client filter drivers, leftover filter drivers from
    uninstalled security products, malware
  beyond_device: network firewall or content filter, router parental
    controls, ISP filtering
  next_checks: pause the security product's network protection for a test,
    check uninstalled-product leftovers, scan with Defender offline
  evidence: blocking rules matched, products detected, test-with-rule-
    disabled results (if the user allowed)

MTU / PERFORMANCE (NET-09..11)
  this_device: NIC offload settings (large send offload, RSS), driver bug,
    Wi-Fi power saving, background upload/backup/sync, malware or heavy
    process saturating the link, failing NIC with error counters rising
  beyond_device: poor Wi-Fi signal or interference, congested channel or ISP
    link, router CPU saturated, duplex mismatch or bad cable (CRC/FCS
    errors), ISP throttling, slow remote server
  next_checks: wired test, speed test to a nearby server, check resource
    monitor for heavy network apps, try another channel/band, compare with
    another device
  evidence: latency/jitter/loss (pathping), link speed, adapter error
    counters, top bandwidth processes

VPN (VPN-01..06)
  this_device: VPN client bug or outdated version, stale virtual adapter
    (TAP/WAN Miniport), conflicting second VPN or security client, local
    firewall blocking the VPN protocol, MTU/IPv6 handling on the client, kill
    switch blocking traffic
  beyond_device: VPN server/concentrator down or at capacity, expired
    credentials/certificates, split-tunnel or route push misconfigured on the
    server, subnet overlap with the home/office LAN, ISP/network blocking VPN
    ports, VPN provider outage
  next_checks: try another protocol/server, connect from another network
    (phone hotspot), reinstall the client and adapter, ask the VPN admin to
    check pushed routes and DNS
  evidence: VPN adapter state, routes added/pushed, DNS servers pushed, MTU
    probe, server reachability on the VPN port

WI-FI (WIFI-01..04)
  this_device: failing Wi-Fi card or antenna cable (laptop), driver/firmware
    bug, power saving, saved-profile or security-type mismatch, radio off,
    interference from USB 3 devices or Bluetooth near the antenna
  beyond_device: weak signal/distance/walls, congested or DFS channel, router
    firmware bug, router at client limit, band steering, MAC filter or WPA
    mode mismatch (WPA3/WPA2), AP needs reboot
  next_checks: move near the AP, forget and re-join, test on 2.4 GHz vs
    5 GHz, connect another device, reboot the AP, update router firmware
  evidence: signal %, channel, band, link rate, BSSID, disconnect reason
    codes from netsh wlan show wlanreport

STACK RESET LADDER (STK-01..04)
  this_device: corrupted Windows installation or network components, failed
    update, malware or LSP/filter drivers from old software, failing NIC or
    disk errors, outdated or corrupt drivers
  beyond_device: the problem was never on this PC (confirm by testing another
    device on the same network)
  next_checks: sfc /scannow, DISM /RestoreHealth, clean-boot to isolate
    software, boot a live USB or test another OS/device, restore point or
    Windows repair as a last resort
  evidence: all prior results, Event Viewer network errors, SFC/DISM output

## 4. USER FLOW (GUI and CLI behave the same)
======================================================================
- After diagnostics, show each finding, its cause, and the recommended fix
  with the commands displayed (plus admin/risk/reboot info).
- GUI: each fix has a "Proceed to Fix" button that opens a confirmation
  dialog listing the exact commands. CLI: the same information and a y/N
  prompt.
- Never auto-run a fix without explicit confirmation (or --yes in the CLI).
  High-risk entries (risk H) require a second explicit confirmation even with
  --yes unless --yes-i-understand-risk is also given.
- Before any change, snapshot the previous state (see catalog). Show what
  changed afterward and how to roll it back.
- After fixing, automatically re-run the relevant check and report whether
  the problem is resolved. If not, offer the next step in the fix ladder.
  When the ladder is exhausted, show the if_unresolved panel (section 3D).
- Be honest about limits: if the problem appears to be outside the device
  (router, ISP, cable, remote server), say so and tell the user what to check
  next. Never claim a fix worked unless the re-check confirms it.

## 5. LOGGING (everything executed must be logged)
======================================================================
- Use Python's logging module with a rotating file handler in
  %LOCALAPPDATA%\NetScope\logs\.
- Log: app start/stop and which mode (CLI, shell, GUI), every CLI command and
  its arguments, every diagnostic check and result, every command executed

  stderr, duration), every GUI button click, every confirmation accepted or
  declined, every pre-fix snapshot and rollback, every unresolved result and
  its probable causes, every error with traceback, and Ctrl+C interruptions.
- Structured format (JSON lines) with a session ID so one run can be traced.
- Same log output regardless of front end. A "View Logs" button in the GUI and
  `netscope logs` in the CLI.
- Export a diagnostic report (system info, results, fix history, unresolved
  findings with probable causes) as txt or json.

## 6. SAFETY RULES
======================================================================
- Only execute commands from the predefined fix catalog and the built-in
  utilities. Never run arbitrary user-supplied strings through a shell. Use
  subprocess with argument lists, not shell=True, and validate all user input
  (hostnames, IPs, ports, adapter names, profile names) before it reaches a
  command. Pass values to PowerShell as parameters, never by string
  concatenation.
- Set timeouts on everything.
- Record previous state before changing it, and show what changed.
- `--dry-run` shows what would run without executing.
- Never export Wi-Fi passwords in clear text by default.
- Never offer to enable SMB1 or disable SMB signing or active probing by
  default. Those stay DETECT-ONLY or behind a second confirmation as
  specified in the catalog.

## 7. TESTING (required, not optional)
======================================================================
Use pytest. All system calls go through the single mockable command-runner
interface.

- Unit tests for every check, using recorded sample outputs of ipconfig, arp,
  netsh, ping, and PowerShell JSON as fixtures. Include localized and
  malformed output cases to prove the parsers are defensive.
- Catalog tests: every entry has an explanation, commands, admin flag, risk
  level, reboot flag, snapshot/rollback (when it changes state), verification
  check, and an if_unresolved block with this_device, beyond_device,
  next_checks and evidence. Every finding maps to valid fix IDs. No duplicate
  IDs. DETECT-ONLY entries contain no commands. Every [VERIFY] entry is
  flagged in the catalog and listed in the README.
- Safety tests: assert no shell=True anywhere, only catalog commands can run,
  malicious input (`8.8.8.8 & del *`, `"; calc`, quotes and backticks in
  adapter or profile names) is rejected or safely passed as a parameter, and
  PowerShell scripts never contain interpolated user input.
- PowerShell layer tests: JSON output parsing, non-English output, missing
  cmdlet fallback to native exe, Constrained Language Mode fallback, process
  startup batching, timeouts.
- Engine tests: simulate failure scenarios by mocking the runner (adapter
  down, APIPA address, no gateway, DNS failing while IP ping works, ARP
  failure, dead proxy, captive portal, wrong clock) and assert the correct
  first failing layer, cause, and suggested fix are returned.
- Fix-flow tests: confirmation required, declined confirmation runs nothing,
  dry-run runs nothing, snapshot taken before change, rollback works,
  re-check runs after fix, a failed fix is reported honestly, non-admin
  sessions are handled, risk H needs a second confirmation.
- If-unresolved tests: not shown while untried fixes remain, shown after the
  ladder is exhausted, causes are ranked using evidence and the "another
  device works" answer, wording stays probabilistic, and the section appears
  in the exported report and logs.
- CLI tests: argument parsing, every subcommand's --help, exit codes, --json
  output validates against a schema, --no-color and piped output contain no
  ANSI codes, non-TTY never prompts, Ctrl+C handling.
- Logging tests: every executed command and button/CLI action produces a log
  entry with the required fields; rotation works.
- GUI smoke tests: the GUI can be constructed and its fix buttons call the
  same engine functions; skip gracefully on headless CI.
- Build tests: after PyInstaller builds, run `netscope.exe --version`,
  `netscope.exe diagnose --json`, and `netscope.exe --help` and check
  results; verify install/uninstall modify and restore PATH and the registry
  correctly (test profile or mocked registry).
- GitHub Actions workflow on windows-latest: run tests, report coverage
  (target 80% or higher on core, fixes, and the PowerShell layer), build the
  exe, run the build tests.
- Manual test checklist for a Windows VM that simulates real failures:
  disable the adapter, set a bad static DNS, clear the gateway, set a wrong
  subnet mask, enable a dead proxy, unplug the cable, stop WlanSvc/Dhcp,
  put a bad entry in the hosts file, set the clock far off, set the profile
  to Public, block port 445 outbound, set a low MTU. Include the expected
  diagnosis, fix, and (for unfixable cases) the expected probable-cause list.
